# Laema HoMM3 creature import, animation and rendering audit

Inspected 2026-10-23, repository `/workspace/Laema`, HEAD `16b4c3b7` (clean `git status --short` at inspection). The initial static audit below used read-only project inspection. Later isolated engine previews are recorded in the final section. No production changes. This is evidence for the research report, not implementation or submission clearance.

## Strong findings

1. **Current high-resolution runtime bindings are present and mechanically sound.** Independently checked 32 `highres_v01` atlases across Archer, Griffin, Swordsman, Monk, Cavalier and Angel (236 populated frame positions). Every file hash matches its local source manifest; every selected group count matches its corresponding preserved original DEF metadata. No populated alpha touches its 768x640 cell border. All unused atlas cells are alpha-empty. Saved details: `runtime-sheet-audit.json`. This excludes these specific causes: wrong selected frame count, cell-edge clipping, accidental nonempty padding, or changed runtime copy bytes. It does not prove anatomical/motion fidelity or compare against the external Art package's individual frames.

2. **Runtime timing is a Laema prototype contract, not a faithful original-game playback.** `scripts/enemy/combat_enemy.gd:442` dispatches attacks to AnimationPlayer; otherwise Death uses 8fps, Idle 8fps, Walk 9fps, and Hurt distributes all frames over a gameplay reaction duration (`:453`, `:458`, `:461`, `:464`). Hurt length can therefore change with the reaction profile. `:299` sets melee AnimationPlayer speed to 1.0. Non-Pikeman attacks use 1.0s resources, often temporary inherited geometry. `assets/prototype/enemy/swordsman/PROVENANCE.md:42` explicitly labels its evenly spaced seven poses a prototype mapping; source 10fps GIFs are illustrative. `assets/prototype/enemy/monk/PROVENANCE.md:61` identifies both attack lengths as temporary. Thus a source-looking sheet can still look wrong in gameplay because it is retimed or coupled to a different physical actor.

3. **Concrete retiming example:** `config/attack_animations/griffin_melee.tres:46` keys at tenths of a second; `:49` samples source sequence `0,1,2,3,4,4,5,6,7,8`, then returns to pose0 at1.0. Pose4 is held twice as long as most others to fit the existing ten-key clock. The 9 original frames are preserved as assets, but their runtime dwell is altered. This is an objective difference from equal-nine-frame sampling; exact original dwell is not recovered here.

4. **Original timing is incompletely specified by assets.** `docs/art/references/heroes3-original-flipbooks/README.txt`, TIMING section: DEF contains sequence order but no per-frame playback times, and viewer10fps is a preview default. `assets/prototype/enemy/pikeman/PROVENANCE.md:50` records a Pikeman base attack duration1.00s read from both installed CrAnim.txt copies; `:54` limits this to data-file base duration, not every original battle-speed setting. The original per-frame timing and other creatures' complete engine timing still require source/runtime reconstruction. Do not call a10fps export original timing.

5. **No evident lossy import degradation or automatic downsize.** Representative imports use `compress/mode=0`, `process/size_limit=0`, `mipmaps/generate=false`, `process/fix_alpha_border=true`, straight alpha (`process/premult_alpha=false`), e.g. `assets/prototype/enemy/pikeman/repaint_v02/attack_right_sheet.png.import:18`. Same settings occur across highres atlases. `scenes/enemy/combat_enemy.tscn:40` explicitly sets texture_filter2 (linear); at unit scale this is conventional for painted art, but fractional movement or display scaling can soften edges. `project.godot:96` has project default nearest, overridden on BodyVisual. No measured runtime blur or halo is claimed. Atlas sprites have wide transparent margins, so neighboring-cell bleed is not supported by present border checks.

6. **Registration arithmetic is consistent, but nominal anchors cannot prove planted feet.** Highres Castle cells768x640, anchor384,448, centered offset0,-128 and scale1 map the anchor to BodyVisual(-11,31); see `scenes/enemy/archer.tscn:33` and corresponding creature manifests. Pikeman cells768x512 use offset0,-192 (`scenes/enemy/combat_enemy.tscn:39`), producing the same foot reference. `scripts/enemy/combat_enemy.gd:473` flips the sprite once, with optional offset reflection; no pre-mirrored texture is bound. Per-frame generated feet can still slide relative to the nominal anchor; that is upstream drawing drift, not solved by setting one anchor in metadata.

7. **Physical presentation remains provisional for several species.** Cavalier retains a humanoid radius30/height180 capsule, temporary copied melee geometry, despite its horse/lance silhouette (`assets/prototype/enemy/cavalier/PROVENANCE.md:42`, `:47`, `:64`). Swordsman carries temporary Pikeman-derived geometry (`assets/prototype/enemy/swordsman/PROVENANCE.md:36`); Monk inherits Archer muzzle64,-108 and melee query tracks (`assets/prototype/enemy/monk/PROVENANCE.md:65`). Archer's detached arrow and Monk's bolt remain original low-resolution sources, explicitly absent from highres package (`assets/prototype/enemy/archer/PROVENANCE.md:23`; Monk manifest projectile entry). These are concrete workflow gaps affecting visual/contact coherence, not proof that the drawing itself is poor.

## Limits for final report

The static audit establishes asset counts, source hashes, alpha bounds and static code behavior. It does not establish an engine-import failure, animation acceptance, or full sprite/hitbox alignment. Artistic desirability and anatomical fidelity need frame/animation visual review separately.
